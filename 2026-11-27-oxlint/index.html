lint 跑太慢、錯誤太多，可以試試 oxlint

10 分鐘技術分享｜2026-11-27

01lint 為什麼沒人看

打開一個放了幾年的專案，跑一次 lint，等很久，跑出來幾千個 warning。看到那個數字，就沒人想修了。

lint 本來是要幫我們擋問題，可是跑太慢、太吵，大家就開始跳過它。

重點不是換工具，是讓 lint 重新有人看。

02oxlint 是什麼

  • Rust 寫的 JS／TS linter，Oxc 專案出品。官方說比 ESLint 快 50 到 100 倍。
  • 內建約 870 條規則：ESLint 核心、TypeScript、React、Next.js、import、jsx-a11y、unicorn、jest／vitest，不用另外裝 plugin。
  • 預設只開 correctness：幾乎確定是 bug 的規則。其他類別（suspicious、perf、style、pedantic）自己一類一類打開。
  • 設定檔 .oxlintrc.json，格式接近 ESLint v8。
  • 型別感知規則（例如沒有 await 的 promise）用 Go 寫的新版 TypeScript 編譯器（tsgo）。

最大的差別不是快，是預設很安靜：只講「這幾乎一定是 bug」的事。

03實測：一個 Next.js side project

Next.js 16，313 個檔案，在自己電腦上跑（Apple Silicon，oxlint 1.94.0）。

oxlint 的 1.4 秒裡，真正 lint 只花 0.11 秒，其餘是 node 啟動。一秒的工具可以每次存檔都跑；十秒的，大家會等 CI。

兩邊抓到的不完全一樣：ESLint 抓很多 any，oxlint 抓到 a11y 和「<a> 應該換成 <Link>」。不是誰比較好，是規則不一樣。

一個小插曲

第一次跑 ESLint 花了 185 秒，報了 27,385 個問題。仔細看，是它掃到了另一個 git worktree 裡的檔案，那兩萬多個都不是這個專案的 code。排除之後，剩 42 個。

lint 錯誤很多的時候，第一步先確認它在掃什麼。

04大專案怎麼導入：和 ESLint 並行

不要一次換掉 ESLint，兩個一起跑。這也是 oxlint 官方建議的順序。

  1. 用工具轉設定 
    npx @oxlint/migrate
    ESLint 9 以上的 flat config 可以直接轉；舊的 .eslintrc 先用 @eslint/migrate-config 轉成 flat config。
  2. 先跑 oxlint，再跑 ESLint 
    "lint": "oxlint && eslint ."
  3. ESLint 關掉重複的規則，只留 oxlint 還沒有的部分。 
    // eslint.config.mjs
import oxlint from 'eslint-plugin-oxlint'

export default [
  ...nextVitals,
  ...(await oxlint.buildFromConfigFile('./.oxlintrc.json')), // 放最後
]
  4. 類別一次開一類：先 warn，觀察一兩週，清乾淨再改 error。
  5. CI 先只擋新的 code：舊的錯誤分批修，第一個 PR 不要改幾百個檔案。

Next.js 專案的設定

{
  "plugins": ["typescript", "unicorn", "oxc", "react", "nextjs", "jsx-a11y", "import"],
  "categories": { "correctness": "error" },
  "ignorePatterns": [".next/**", "out/**"]
}
注意：寫了 plugins 就會蓋掉預設的 plugin，所以預設的 typescript、unicorn、oxc 要自己寫回去。

先修 correctness：那些幾乎都是真的 bug，修了有感，PR 也好審。

05什麼時候不要換

  • 有自己寫的 ESLint 規則：oxlint 的 JS plugin 還是 alpha，不是每個 ESLint plugin 都能跑。
  • 依賴的規則 oxlint 還沒有：官方也說，卡住的話留在 ESLint 是正常的選擇。

所以建議是並行，不是替換：oxlint 擋大部分、跑得快；ESLint 留給 oxlint 還沒有的那幾條。

補充：TypeScript 7 之後，typescript-eslint 還需要 TypeScript 6 的 API，Next.js 文件教大家讓兩個版本並存。oxlint 的型別規則直接用 tsgo，沒有這個問題。另外 Next.js 16 已經移除 next lint，本來就要動一次 lint 設定。

結尾

你上一次認真看 lint 的 warning 是什麼時候？如果答案是「很久了」，可能不是大家不在乎，是 lint 太慢、太吵了。
